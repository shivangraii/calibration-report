# LLM Calibration Study (ECE on SimpleQA, OpenAI API)

Question answered: **does an LLM's confidence match how often it is actually right?**
Design: inference only (no training), 1,100 SimpleQA questions, confidence from token log-probabilities, ECE + reliability diagram.

---------------------------------------------------------------------

## 1. Will it work with the OpenAI API?

Yes, with two conditions.

1. **Use a non-reasoning chat model.** The Chat Completions API returns token `logprobs` for models such as `gpt-4o`, `gpt-4o-mini` and `gpt-4.1`. Reasoning models (o-series, and likely the GPT-5 family) generally do not return logprobs or accept `temperature`. Model names change, so run the pilot (Step 3 below): it fails immediately with a clear message if a model doesn't support logprobs.
2. **Pick a model that can actually answer SimpleQA.** SimpleQA is adversarially hard, so small models score very low. If accuracy is under ~10%, almost every bin is "wrong" and ECE just equals mean confidence. Recommended design:
   - **Main model:** the strongest logprob-capable model you can afford (e.g. `gpt-4o` or `gpt-4.1`).
   - **Second model:** a smaller one (e.g. `gpt-4o-mini`) to add a "does size affect calibration" comparison.
   - **Optional:** `--mode verbal` (model states its confidence 0-100) to compare against token probability.

Cost: 1,100 short questions plus grading is a small number of tokens, typically a few dollars at most per model. Check current prices on OpenAI's pricing page and set a spend limit in your OpenAI dashboard.

## 2. Folder / file management

```
calibration_project/
├── README.md                  <- this file
├── config.py                  <- ALL settings (models, temperature, bins, prompts)
├── requirements.txt
├── .gitignore                 <- keeps keys/venv out of git
├── 01_prepare_data.py         <- validate CSV, merge tiny categories
├── 02_run_inference.py        <- model answers + confidence (resumable)
├── 03_grade_answers.py        <- CORRECT / INCORRECT / NOT_ATTEMPTED + audit sheet
├── 04_analyze.py              <- ECE, Brier, AUROC, tables, figures
├── data/
│   ├── raw/                   <- original CSV. NEVER edit. Read-only.
│   └── processed/questions.csv<- generated by step 1
├── outputs/
│   └── <model_name>/          <- one folder per answer model
│       ├── answers_logprob.jsonl      <- raw model outputs (source of truth)
│       ├── graded_logprob.jsonl       <- grades
│       ├── audit_sample_logprob.csv   <- 100 rows for manual check
│       ├── run_meta_logprob.json      <- model, params, prompt, SDK version, timestamps
│       └── analysis_logprob/          <- everything that goes in the paper
│           ├── metrics.json, bin_table.csv, by_difficulty.csv,
│           │   by_category.csv, confidence_variants.csv, results_merged.csv
│           └── reliability.png / reliability.pdf
└── paper/                     <- draft, final figures copied here
```

Rules:
- **Raw is sacred.** `data/raw` and the `.jsonl` files are append-only records; never hand-edit them. Fix problems by re-running scripts.
- **Everything is reproducible from code.** If a number is in the paper, it must come from `metrics.json` or a CSV in `analysis_*`.
- **One folder per model.** Never mix models in one file. `mode` (`logprob` / `verbal`) is part of every filename.
- **Scripts are numbered and idempotent.** Re-running skips finished work, so a crash or rate limit costs nothing.
- **Never hard-code or commit the API key.** Use the environment variable only.
- **Back up** the whole `outputs/` folder (Google Drive / GitHub private repo) after each model finishes. API calls cost money; the JSONL files are your receipts.
- **Freeze before writing results.** When final runs are done, zip `outputs/` as `final_YYYYMMDD.zip` and don't re-run (non-zero nondeterminism even at temperature 0).

## 3. Workflow (run in order)

**Setup (once)**
```bash
python -m venv .venv
source .venv/bin/activate            # Windows: .venv\Scripts\activate
pip install -r requirements.txt
export OPENAI_API_KEY="sk-..."       # Windows PowerShell: $env:OPENAI_API_KEY="sk-..."
```

**Step 1: prepare data**
```bash
python 01_prepare_data.py
```
Check the printed counts (1,100 rows, 0 duplicates).

**Step 2: pilot (always do this first)**
```bash
python 02_run_inference.py --limit 20
python 03_grade_answers.py
python 04_analyze.py            # ECE on 20 points is meaningless; this only tests the pipeline
```
Open `outputs/<model>/answers_logprob.jsonl` and confirm the answers are short and `conf_mean` values look sensible. The pilot's results are kept; the full run continues where it stopped.

**Step 3: full run**
```bash
python 02_run_inference.py                      # main model (config.ANSWER_MODEL)
python 03_grade_answers.py
python 04_analyze.py
```

**Step 4: second model (comparison)**
```bash
python 02_run_inference.py --model gpt-4o-mini
python 03_grade_answers.py  --model gpt-4o-mini
python 04_analyze.py        --model gpt-4o-mini
```

**Step 5 (optional): verbalized confidence**
```bash
python 02_run_inference.py --mode verbal
python 03_grade_answers.py --mode verbal
python 04_analyze.py       --mode verbal
```

**Step 6: audit the grader**
Open `audit_sample_logprob.csv`, fill the `human_grade` column for the 100 rows (CORRECT / INCORRECT / NOT_ATTEMPTED), save, then re-run `04_analyze.py`. `metrics.json` will now contain `audit_agreement`. Report it in Section 3.5.

**Step 7: write the paper** (mapping below).

## 4. What each output is for

| Output | Paper section |
|---|---|
| `metrics.json`: accuracy, mean confidence, ECE, 95% CI, Brier, AUROC | Results (headline table) |
| `bin_table.csv` | Results (bin-wise table) |
| `reliability.png/pdf` | Results (main figure; histogram panel shows how confidence is distributed) |
| `by_difficulty.csv`, `by_category.csv` | Discussion (where is it worst?). ECE is blank for groups under 30 questions |
| `confidence_variants.csv` | Discussion / ablation: mean vs geometric mean vs first-token vs min-token |
| `run_meta_*.json` | Section 3.10 (reproducibility: model, version, params, prompt) |
| `audit_agreement` | Section 3.5 (grader validity) |

Interpretation: `gap = mean_conf - accuracy`. Positive = overconfident, negative = underconfident. AUROC near 0.5 means confidence cannot tell right answers from wrong ones; ECE and AUROC measure different things (calibration vs discrimination), so report both.

## 6. Troubleshooting

| Problem | Fix |
|---|---|
| `API rejected the request ... logprobs/temperature` | Model is a reasoning model. Use a non-reasoning chat model. |
| `RateLimitError` / many failures | Lower `WORKERS` in `config.py` (try 3), re-run: finished questions are skipped. |
| `AuthenticationError` | `OPENAI_API_KEY` not set in this terminal session. |
| Almost all confidences > 0.9 | Normal for LLMs. The histogram panel shows it; the equal-mass ECE in `metrics.json` handles this. |
| Very low accuracy | Use a stronger model (see section 1). |
| Want to re-run from scratch | Delete that model's `outputs/<model>/*_<mode>.*` files (not `data/raw`). |
